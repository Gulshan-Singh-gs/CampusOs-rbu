02. UX Discovery (02_ux_discovery.md)

2.1 Product Positioning Conflict

The product suffers from an acute identity crisis, attempting to occupy four divergent mental models simultaneously:

Identity Credential / Campus ID Card: Prominently displays official badges, student photo placeholders, and registration numbers.

Official Academic Transcript: Exposes institutional metrics (GPA, attendance, standing).

Self-Authored Professional Resume / Portfolio: Hosts personal bios and interactive skill-building features.

Web3 / Cryptographic Attestation Document: Features cryptographic hashes and zero-trust verification claims.

A. Student Owner (Profile Subject)

Core Job to Be Done: "When I share my university credentials with prospective employers, I want to prove my academic standing and skills are verified by my institution, so that I can secure internships without exposing myself to identity theft or grade stalking."

Primary Anxiety: Loss of control over sensitive academic records (GPA, registration number) published publicly on a non-university domain.

B. Recruiter / Hiring Manager

Core Job to Be Done: "When evaluating a student applicant, I want an unambiguous, tamper-evident signal that their enrollment, GPA, and skills are certified by their university, so that I can make hiring decisions without manual background checks."

Primary Anxiety: Detecting student-authored fraud or unverified academic claims masked behind technical jargon.

C. Faculty / Department Verifier

Core Job to Be Done: "When endorsing student capstone projects and academic honors, I want an authenticated review portal, so that departmental recognition carries institutional legitimacy."

Primary Anxiety: Administrative liability, unauthorized issuance of university honors, and lack of an official audit log.

D. Anonymous / Casual Visitor

Core Job to Be Done: "When opening this link, I want to understand what organization produced it and why I have access, so that I can assess whether it is legitimate."

Primary Anxiety: Suspecting phishing, malware, or an accidental data breach.

04. UX Heuristic Evaluation (04_heuristic_evaluation.md)

┌────────────────────────────────────────────────────────────────────────┐
│                      HEURISTIC SEVERITY SUMMARY                        │
├─────────────────┬─────────────────┬──────────────────┬─────────────────┤
│ P0 (Critical): 4│ P1 (High): 3    │ P2 (Medium): 2   │ P3 (Low): 1     │
└─────────────────┴─────────────────┴──────────────────┴─────────────────┘



H1: Visibility of System Status

Finding: The page lacks session status, synchronization timestamps, viewer role indicators, and interactive feedback.

User Impact: Users cannot determine whether they are viewing a draft, a live record, or a cached preview.

Severity: P1 (High)

Recommendation: Introduce a status banner: "Viewing as Guest • Read-Only • Last verified by RBU Registrar: Oct 5, 2026".

H2: Match Between System and Real World

Finding: Heavy reliance on engineering buzzwords ("Zero-Trust Identity", "Document Hash") that do not correspond to user tasks.

User Impact: Obscures actionable information behind technical jargon.

Severity: P2 (Medium)

Recommendation: Replace technical assertions with plain-language assurances: "Officially Issued Transcript", "Cryptographically Signed Document".

H3: User Control and Freedom

Finding: Complete absence of privacy toggles, edit capabilities, share configurations, or account preferences.

User Impact: Students are trapped with an immutable, public profile that exposes private records.

Severity: P0 (Critical)

Recommendation: Implement a Student Management Portal with visibility checkboxes ([ ] Display GPA on Public Profile).

H4: Consistency and Standards

Finding: Buttons (Add Skill, Add First Skill) adopt primary CTA visual styling but execute no function.

User Impact: Destroys user trust in interface affordances.

Severity: P0 (Critical)

Recommendation: Remove non-functional buttons from public view; render them only for authenticated profile owners inside an active edit session.

H5: Error Prevention

Finding: Sensitive academic data is published to the public internet without explicit confirmation or access gates.

User Impact: Severe exposure of student educational records.

Severity: P0 (Critical)

Recommendation: Restrict full profile access behind role-based authentication or scoped access tokens.

H6: Recognition Rather Than Recall

Finding: Alphanumeric UID (RBU21CSE***) requires external institutional knowledge to decode.

User Impact: External recruiters cannot deduce program, degree level, or cohort year from the raw string.

Severity: P2 (Medium)

Recommendation: Expand institutional codes into natural language labels: "Roll No. 045 • B.Tech Computer Science & Engineering (Class of 2025)".

H7: Flexibility and Efficiency of Use

Finding: No export features (Download PDF, Verified Credential JSON, Print View).

User Impact: Users cannot easily attach credentials to job application portals.

Severity: P1 (High)

Recommendation: Add a "Download Official Summary (Signed PDF)" export function.

H8: Aesthetic and Minimalist Design

Finding: Decorative cryptographic pseudo-strings clutter the footer without delivering user utility.

User Impact: Visual noise that dilutes genuine institutional branding.

Severity: P3 (Low)

Recommendation: Collapse technical metadata into a collapsible "Verification Details" drawer.

H9: Help Users Recognize, Diagnose, and Recover from Errors

Finding: Failed interactions (dead buttons) trigger zero visual cues, error dialogs, or fallback states.

User Impact: Users assume system crash or device failure.

Severity: P0 (Critical)

Recommendation: Provide clear inline error and empty-state messaging for any offline or pending feature.

H10: Help and Documentation

Finding: Zero documentation, FAQs, or contact info regarding how credentials are issued, corrected, or verified.

User Impact: Users with data errors have no remediation path.

Severity: P1 (High)

Recommendation: Include an accessible footer help link: "Dispute or verify this record with the Academic Registrar".

05. Comprehensive UI Audit (05_ui_audit.md)

5.1 Visual Hierarchy & Spatial Grid

Page Grid: The layout uses a centered single-column container (max-width ~768px on desktop). While focused, it compresses high-density academic data into vertical ribbons.

Spacing Scale: Inconsistent padding scales across cards (e.g., 24px on the identity card vs. 12px on inner metric cards), creating an unbalanced visual cadence.

Visual Anchors: The student's name competes directly with the page title for primary optical weight.

5.2 Typography System

Font Stack: Standard system sans-serif font stack. Clean and readable, but lacks institutional dignity and academic distinction.

Typographic Scale:

H1 (Page Title): ~24px / Semi-Bold

H2 (Section Titles): ~18px / Medium

Metrics (GPA/Attendance): ~28px / Bold

Captions & Footers: ~11px–12px / Regular

Hierarchy Flaw: Metric numerical values (8.8, 92%) dominate visually without adequate contextual labeling, causing scanning eyes to see raw numbers before understanding their meaning.

5.3 Color Palette & Semantic Tokens

Primary Surface: Crisp white (#FFFFFF) with light gray canvas (#F9FAFB).

Border Strokes: Muted gray (#E5E7EB).

Semantic Status Colors:

"Verified Student": Emerald green pill (#DEF7EC bg, #03543F text). Strong contrast and appropriate semantic coloring.

"In Good Standing": Indigo/blue text badge.

Contrast Vulnerability: Muted captions in the footer (#9CA3AF) on light gray backgrounds fail the WCAG 2.1 AA 4.5:1 minimum contrast ratio for normal text (achieving only ~2.8:1).

| Skill Container | Display endorsed competencies | Empty state communicates deficiency rather than pending status. | Implement guided setup wizard or hide from public recruiters until verified. |

07. Trust, Privacy, and Credibility Analysis (07_trust_privacy_review.md)

7.1 Trust & Institutional Legitimacy

Hosting Credibility: The URL campusos-rbu-owv.pages.dev signals an unverified hobbyist deployment or student capstone project. Authentic academic platforms operate under institutional domains (e.g., credentials.rayatbahrauniversity.edu.in).

Visual Authority: The absence of verified institutional contact details, registrar seals, and accreditation notices creates skepticism.

The "Security Theater" Paradox: Incorporating unverified technical assertions like "Zero-Trust Identity" and pseudo-hashes produces the opposite of trust: technical reviewers recognize the claims as unbacked, while non-technical users find them alienating.

7.2 Student Privacy & Regulatory Exposure

Unprotected Academic Records: Public exposure of GPA, attendance percentages, and internal registration IDs violates core student privacy expectations (aligned with global standards such as FERPA, GDPR, and India's Digital Personal Data Protection Act).

Identity Harvesting: An exposed student UID coupled with legal name and program details provides sufficient data for social engineering or fraudulent student portal access.

Consent Deficit: There is no indication that the student consented to public indexation of their academic record.

7.3 Multi-Variable Risk Matrix

| Risk Factor | Affected Stakeholder | Impact Level | Likelihood | Mitigation Strategy |
| Student Data Exposure | Student Owner | Critical (P0) | High (Live) | Require authentication; redact GPA and UID on unauthenticated views. |
| Institutional Brand Damage | University | High (P1) | High (Live) | De-escalate security claims; migrate to institutional domain. |
| Recruiter Distrust / Discard | Student Applicant | High (P1) | High (Live) | Replace hardcoded text with verifiable digital signature certificates. |
| Inoperable Interaction | All Users | Medium (P2) | Certain (100%) | Remove non-functional action triggers from public view. |

8.1 Detailed WCAG 2.1 Audit Findings

WCAG 1.4.3 Contrast (Minimum):

Issue: Subtitle captions (#9CA3AF) against card background (#FFFFFF) yield a 2.8:1 contrast ratio.

User Impact: Low-vision and aging users cannot read verification and timestamp metadata.

Remediation: Shift secondary text tokens to #4B5563 (7.0:1 contrast ratio).

WCAG 2.1.1 Keyboard Navigation:

Issue: The Add Skill element receives tab focus, but activating it with Enter or Space triggers no event or focus transfer.

User Impact: Motor-impaired users navigating via switch devices or keyboards encounter a dead-end affordance.

WCAG 2.4.4 Link Purpose (In Context):

Issue: The document hash string has no accessible description or context explaining its function.

User Impact: Screen readers announce a confusing 28-character alphanumeric string without indicating its purpose.

WCAG 3.1.2 Language of Parts:

Issue: Technical acronyms ("UID", "GPA", "SHA256") lack <abbr> wrappers or semantic expansion.

WCAG 4.1.2 Name, Role, Value:

Issue: Custom status indicators (pills) rely on <div> tags lacking role="status" or aria-label declarations.

15. Inclusive Design & Accessibility Specification (15_accessibility_specification.md)

Target Compliance: WCAG 2.1 Level AA & Level AAA for typography contrast.

Keyboard Focus Navigation: Dedicated tabindex="0" on interactive credential cards with clear :focus-visible styling (outline: 2px solid #2563EB; outline-offset: 2px).

Screen Reader Announcer Architecture: Status updates (e.g., verifying signature, copying shareable link) must announce via an aria-live="polite" region.

Touch Target Sizing: All buttons and interactive pills on mobile viewports must enforce a strict min-height: 48px and min-width: 48px clickable tap boundary.

18. Final Executive UX/UI Report (18_final_ux_ui_report.md)

Executive Overview & Verdict

Is the current page user-ready? No.

Current State Classification: Static early-stage proof-of-concept prototype.

Primary Risks: Critical privacy exposure of student academic records, complete lack of interactive functionality, and reputational risk stemming from ungrounded security assertions.

Strategic Recommendation: Do not circulate or market the current deployment to students or corporate recruiters. Transition the prototype into an authenticated, institutional credential service adhering to the redesigned IA, component specifications, and privacy framework outlined in this document.

Report Compiled & Signed by Senior UI/UX Systems Engineering Lead.
